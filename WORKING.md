# WORKING.md

This file serves as the handoff between high-context planning and implementation.

Use this document to store prompts, implementation plans, architecture decisions, and detailed specifications generated by larger-context AI models. These prompts may exceed the practical context window of faster, lower-token models.

The responsibility of the implementation model is to:

* Read and fully understand the instructions contained in this document.
* Treat the contents as the source of truth unless explicitly overridden.
* Execute the requested changes as a senior software engineer would.
* Preserve the existing architecture, coding standards, and project conventions.
* Avoid unnecessary refactoring or scope creep.
* Ask for clarification only when requirements are genuinely ambiguous or conflicting.
* Complete the implementation with production-quality code, not placeholders or partial solutions.

### Workflow

1. A high-context model performs analysis, planning, architecture, and writes implementation instructions into `WORKING.md`.
2. A fast implementation model reads this file.
3. The implementation model executes the requested work faithfully and efficiently.
4. If additional work is required, the planning model updates `WORKING.md`, and the cycle repeats.

Think of this file as a senior developer handing detailed implementation tasks to a junior developer. The planning has already been completed—the objective is accurate, high-quality execution.
